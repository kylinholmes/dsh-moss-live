## 真实供应商核查

同一 DSH 凭据直接请求 `GET https://api.mosi.cn/v1/models`，在 `2026-11-11T11:01:22Z` 返回 HTTP 200、15 个模型，无任何 `moss-live-*` ID。脱敏原始 JSON 位于忽略的 `.superpowers/diagnostics/moss-models-raw.json`。Key 只在宿主内存解析，未打印或写入报告。

正式探测器调用 `moss-live-1.0` 实际通过 WebSocket、session.update、media.configure：PCM16 单声道，输入 16 kHz、输出 48 kHz。测试未创建聊天历史、发送麦克风音频或运行外部 Agent。快照 ID 当次返回不兼容；不能据此推断永久不可用。

结论仅限该时间、端点和 Key：目录漏列一个实际可调用的稳定 Live 模型。供应商内部原因未知，不能归因于 DSH/插件过滤，也不能承诺其他账号权限。

官方：[模型列表](https://platform.moss.cn/docs/reference/models/)、[实时协议](https://platform.moss.cn/docs/reference/moss-live/)。

## DSH 开发环境限制

连续修改包元数据、Host 模块并热重载后，DSH rc.1 的 client-modules 可能保留已停止来源的图记录，表现为后端关闭而旧入口仍在。实际 installed 代码的内部插件停止通知可先于 Loader entry 移除，增量 sources 未再被标脏；只读内存复现实证需要第二次通知才删除。重启隔离验收 Host 后，未再改代码的正式开关验收得到 nav=0、route=404、micStop=1、active=0，重新启用恢复原模型/外观。

官方插件管理页的 checked 来自库存快照，实际操作后本次观察到其自动加载结果滞后；手动点击原生「刷新」后与 Host 一致。框架已实现操作后 load 和 changed 订阅，不能将此现象描述为完全没有自动刷新。验收同时检查真实 HTTP、入口和媒体资源，不仅检查开关旧值。

这两点未用插件私有 DOM 或自造启停协议绕过；日常试用使用已构建并重新启动的本地 Host。修改包元数据后的开发环境可重启隔离 Host，用户 profile 不被改写。

## 新建入口与公开发布补充

用户后续确认左侧 MOSS 语音应为新建入口。现在新建和返回分别使用 `main:moss` / `main:moss-session`，同一 VoiceView 和原生 UI；图标槽仅负责图标，不拦截侧栏 DOM 或接管宿主按钮。浏览器实测：旧历史返回保持原 id；侧栏进入 session-id 为空的待开始页，POST=0；按开始 POST=1、新 id 与旧不同。后台通话在新建页保持；模拟创建失败后 active=1、连接数不增加；胶囊/历史返回同一新 id，额外连接=0，320px 无横向溢出。
