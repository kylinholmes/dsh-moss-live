# 独立语音会话与输出设备

用户要求新增输出设备按钮，普通文本会话不显示语音控制条，每个语音 Session 独立；对于并存通话，用户明确选择「暂停」。本次为已有实现的修正，延续已授权的本机修改、测试和公开插件交付。

## 行为

- 每个 MOSS Session 拥有独立 VoiceController。切换到另一主会话时，原通话自动暂停并释放媒体/连接，保留其字幕、静音和恢复状态。切回显示该 Session 的状态，点击恢复，不自动开麦。
- 同一语音会话的全屏、历史及所属子任务视图切换不暂停、不重连。新建入口仍不创建 Session；明确开始才创建。进入新建页暂停前一通。
- 普通文本会话保留原输入框，不显示其他语音 Session 的全局条。语音历史使用自己的 composer；所属子任务可显示对应父语音控制条。其他全局面板不显示通话条。
- 暂停、静音、结束和恢复都明确携带 Session id。页面卸载和插件停用释放所有通话资源。
- 语音页/历史控制栏增加「输出设备」按钮，使用官方 Settings 图标、Button、Modal、Menu；暂停与开始前均可打开。窄屏仍保持至少 44px 点击目标。
- 输出选择使用实际 AudioContext.setSinkId，不重连模型。提供系统默认、授权可见设备和刷新；可用时通过 selectAudioOutput 请求权限，否则显式请求短暂麦克风授权后释放以枚举。
- 输出偏好只存当前浏览器本地，不写共享 DSH provider/凭据配置。切换失败保留上一设备；设备拔出或保存的 id 失效时回到系统默认并提示。浏览器没有 setSinkId 时说明通过系统选择，不伪装支持。

## 方案与决定

现有单控制器会覆盖前一通状态；仅保存一个旧 id 无法隔离暂停、字幕和异步回调。采用 Session → VoiceController 注册表，沿用已经验证的单通话生命周期实现。多个通话同时采集播放不符合用户「暂停」选择，因此只允许当前 Session 恢复媒体。

框架 Session/mainView 是选中会话的唯一来源。注册表订阅原生列表及面板，禁止用最后一通正在运行的语音覆盖普通文本选择。不改宿主 DOM，不新增会话存储。

设备依据：[Chrome Web Audio 输出接口](https://developer.chrome.com/blog/audiocontext-setsinkid/)、[W3C Audio Output](https://www.w3.org/TR/audio-output/)。手机系统是否暴露耳机/扬声器由浏览器决定，以能力检测及实际调用结果为准。
