# DSH 内的独立 MOSS 语音 Chat：重做设计

日期：2026-11-11。状态：草案已因新的会话集成要求暂停确认，尚未实施。

> 已被最新产品决定取代：当前为「MOSS 主对话 + DSH 子 Agent 委派」，不做常驻三方群聊。视图采用插件接入、局部替换；语音会话锁定语音模型、禁用模型选择并简化输入区。以 [`../../requirements.md`](../../requirements.md) 中的最新要求为准；本文保留作设计过程记录，不可直接实施。

> 最新讨论：用户希望更高集成度，复用 DSH 的会话与提示词等机制，并担心 MOSS 与 Agent 同时响应。下文“只在内存保存、独立管理提示词”的方案已不作为当前决定。正在讨论“同一 DSH Session，按文字/语音模式控制输入路由与回答所有权”；需完成框架可行性验证、更新设计并重新确认，不能直接按旧草案实施。

## 1. 已确认的产品定位

这是一个住在 DSH 里的简单语音 Chat。MOSS-Live 负责实时对话；DSH 提供入口、登录鉴权、配置、凭据和插件生命周期。

用户已明确要求从头重做，并选择保留独立 MOSS 会话。语音不进入 DSH Agent loop，不写入 DSH 聊天记录，不参与 Agent 的工具执行。未来可能考虑 MOSS 与 Agent 分工协作，本期不实现，也不预建多 AI 协调接口。

本期交互：侧边栏「实时对话」；展开为覆盖 DSH 框架的语音面板，包含语音球、状态和双方当前轮字幕；可收起为底部胶囊；点击胶囊展开，点击其结束按钮释放会话。点击语音球可打断回复；讲话时可自然插话。用户要求视觉参考 ChatGPT 实时语音模式，增加流体与语音反馈动效；具体外观以正在制作的可点击原型反馈为准。

## 2. 路径比较与选择

| 路径 | 得失 | 选择 |
| --- | --- | --- |
| 在现有 DOM 拼接实现上继续修补 | 变更较少，但仍保留错误的 UI 所有权与共享状态设计 | 用户要求从头重做，不选 |
| 独立 MOSS Chat，以正式 DSH 插件接入 | 产品保持简单，React 槽位、鉴权、配置与资源释放使用框架机制 | 本设计采用 |
| 把语音并入 DSH Chat/Agent | 可共享上下文和工具，但需要新的会话、权限和执行语义 | 用户明确本期不做 |

实现选择由开发方提出：TypeScript、React，以及 esbuild 构建；框架基线固定为设备运行中的 DSH `0.2.2-rc.1`。不升级宿主或改其他插件。

## 3. 组成与边界

```text
DSH sidebar.footer.action ── 打开/展开 ──┐
                                      ▼
DSH shell.overlay ── React 语音界面 ← 会话控制器
                                      │
                     麦克风采集 / 播放队列 / MOSS 事件
                                      │
                   同源 HTTP 配置 + WebSocket
                                      │
              Host 插件：DSH Connection 鉴权、凭据、代理
                                      │
                    MOSS-Live realtime
```

每次客户端 `apply` 创建自己的会话控制器。控制器持有网络与媒体资源，并提供稳定快照和订阅供 React 使用；组件只处理展示和用户动作。不使用模块级可变单例保存会话。

界面与 MOSS 连接分开，避免它们互相拥有生命周期。分离仅为本期测试与资源管理服务，不引入多模型抽象、消息总线、持久化会话或后台 Agent。

## 4. DSH 接入契约

- 包继续以 `dsh.bundle` 贡献一个宿主行，通过 `exports["./client"]` 与 `dsh.client` 提供浏览器半侧。
- `dsh.client.inject` 明确列出使用的服务及槽位所有者包；导出的客户端 `inject` 声明 Cordis 服务依赖。二者不可混用。
- React 等共享模块使用宿主模块表，避免打入第二份 React。esbuild 生成 DSH 规定的 lazy CJS closure factory；不用去掉 export 的文本拼接构建。
- 用 `ctx.slots.inject(...ctx.slots.register(...))` 注册真实 React 组件。侧边栏按钮使用 owner 提供的 `wide`，适配展开与收起状态。
- 覆盖层在 `shell.overlay` 内渲染，绝对定位铺满框架；由宿主分配几何范围。不查找宿主的中文文本、不插入宿主 DOM、不通过 document.body 兜底。
- 展开面板使用共享 `useModalLayer` 处理焦点、Escape 和焦点恢复。收起时胶囊不作为模态框。
- 注册、样式和控制器清理由 `ctx.effect` 管理。槽位 owner 卸载时不会遗留组件；插件卸载时停止所有网络和媒体资源。
- 宿主声明 `webServer`、`connection` 和 `credentials` 服务依赖；自定义 HTTP 和 WS 升级都通过 `connection.requestRejection`。
- 导出 Schemastery `Config`，使普通 DSH 插件配置界面能够校验字段。

## 5. 配置和凭据

使用现有 DSH 插件配置能力，本期不新建专用设置页：

| 字段 | 默认值与含义 |
| --- | --- |
| `model` | `moss-live-1.0` |
| `voice` | 空，使用上游默认音色 |
| `personaName` | `MOSS`，语音助手称呼 |
| `personaPrompt` | 提供可编辑的简短语音助手人设；上限遵循 MOSS 8000 Unicode 字符契约 |
| `instructions` | 可编辑的对话规则；上限遵循 MOSS 16000 Unicode 字符契约 |
| `apiKeyRef` | `MOSS_LIVE_API_KEY`，标注为凭据引用 |

每次新连接从 `credentials.resolve(apiKeyRef)` 读取当前值。由 DSH 凭据提供方决定凭据存储与环境变量的优先级，不在插件中实现第二套凭据系统。

浏览器配置接口只返回模型、音色、人设和对话规则。API Key 只用于固定 MOSS 上游的 Authorization 握手头，不进入 URL、客户端、构建产物或日志。

### 系统提示词的自动初始化

用户要求系统提示词像普通 Agent 一样在会话建立时自动应用，不依靠手工发送聊天消息。按 MOSS 官方语义区分 `session.persona`（身份、人设）和 `session.instructions`（本次对话规则）。初始化顺序为 attach_session → session_attached → 可选 change_voice/voice_changed → session.update → session.updated 确认无错误 → 媒体模式与麦克风输入。初始化失败不开始采集。

通过 DSH Config 管理这些字段，每次新会话自动初始化；不将人设作为用户消息写入对话历史。默认人设建议为自然、友好的中文语音助手，回答简洁、适合朗读；用户可以修改或明确清空以采用上游默认人设。

DSH 的 `systemPrompt.assemble` 会协同收集提示词、工具和运行上下文，本期不会把原 Agent 装配结果直接复制给独立 MOSS Chat。它没有对应的工具与执行循环，这样复制会导致人设描述与实际能力不符。提示词独立管理不影响使用 DSH 的配置与凭据机制。未来协作功能需另行设计实际授权能力与上下文投影。

配置修改用于下一次新会话；若 DSH 重载插件，当前语音会话随插件停止并释放资源。

## 6. 媒体与协议

- 麦克风采集优先使用 AudioWorklet；在音频渲染线程按实时速度组装 16kHz、单声道 PCM16LE 定长帧。采样率不匹配时进行跨块连续重采样，不丢弃每个采集块的余数。
- Worklet 打包为脚本文本，通过短生命周期 Blob URL 加载；不把 JavaScript 当作 DSH 图片 asset 提供。浏览器不支持 AudioWorklet 时给出明确错误，本期不维护已废弃的 ScriptProcessor 第二条采集路径。
- 按 MOSS tagged-v1 协议传输输入，播放期间持续送入麦克风音频。
- 48kHz 下行 PCM 与前一条 `response.audio.context` 配对，按顺序排程；缺少归属或格式错误时不猜测归属。
- 片段实际播完后发送 `playback.chunk.completed`；收到该回复 audio.done 且队列实际排空后发送一次 `playback.completed`。
- 打断时先确认已播完片段，再停止剩余播放并回报当前未完成队首片段的实际毫秒数。排程等待、已确认片段和未来队列不计入该值。
- 处理停止、打断和回复终态；同一回复不重复回执，已停止回复的迟到音频不恢复播放。字幕按当前轮的全量文本更新。

## 7. 生命周期和错误

一次启动使用独立代次标识。结束、重开或卸载后，旧的麦克风授权、配置请求或连接回调失效；随后返回的 stream 必须立即停止。

结束时释放麦克风轨道、worklet、音频节点、AudioContext、WebSocket、回调、订阅和临时 URL，清空内存字幕。收起面板只改变视图，会话继续。

缺少凭据、拒绝麦克风、配置失败和断线均在面板给出可读原因并立即停止媒体。错误提示保留到用户关闭或重试；不继续采集，也不自动重连出新会话。

代理限制单帧大小、上游握手前的排队字节和发送积压，并设置连接超时。拥塞时结束会话，让用户重试；不积压越来越旧的实时音频。插件卸载主动终止两端连接。

旧 `/diag` 路由与上报全部删除。

## 8. 验收标准

1. 对照固定 DSH 文档审查 manifest、Config、依赖和 effect；独立审阅者检查接入契约。
2. 原实现上的两条回归用例确实失败：匿名配置访问不应 200；入口必须由已声明的 React 槽位渲染。
3. 在新版上验证鉴权后的配置和真实 HTTP/WS 转发；匿名、异源、错误方法、缺少凭据、拥塞和卸载行为都有用例。
4. 使用可控音频时钟验证真实播放进度、片段回执、整轮回执、打断、迟到帧与跨轮隔离。
5. 使用 React 渲染与受控媒体验证入口、展开、收起、展开恢复、结束、错误提示、反复激活卸载和异步授权竞态。
6. 通过本机 Edge 在 `http://127.0.0.1:42387/` 验证当前设备部署；检查桌面与手机尺寸、控制台、网络、面板范围、焦点和键盘行为。
7. 使用已配置凭据进行受控语音回放，验证转写、下行音频和播放回执；真人麦克风与自然插话的听感需要实际设备交互验证，报告中与自动回放明确区分。
8. 新版不新增 DSH 聊天记录，不调用 Agent，不改变其他插件。
